# SEO and editorial operations

2026-10-26 · Static-first implementation. No production domain, indexability or Search Console verification is claimed.

## Site identity and metadata

Set `SITE_URL` only to the owner's approved HTTPS origin, without path/query/credentials. `SITE_INDEXABLE=false` remains the default. Build-time content and metadata require a rebuild after changing publication/domain settings. No database, CMS or runtime image/social-card service is introduced; only the existing minimal contact endpoint is dynamic.

`src/lib/seo/site.ts` owns per-page Metadata API output: the existing root title template, unique title/description, canonical, Open Graph and Twitter large-image cards. Absolute canonical/image URLs are omitted when the real origin is absent; the preview must not invent a domain or leak localhost URLs. Work query filters share the static Work page canonical, rather than creating keyword variants.

Twelve static 1200 × 630 PNG share cards are generated by `scripts/seo-images.mjs`. Each uses the unchanged supplied raster mark and code-native type/palette composition. They contain no invented client work or contact details. See `social-assets.json` for source/logo/output hashes. Article/case templates use the generic Insights/Work card until a genuine approved article/case asset is supplied; no fake screenshot is generated. No social handle is invented.

## Publication and schema

- Organization/WebSite: minimal confirmed MOTEKRA name, official supplied mark, configured URL and stable IDs. No legal name, address, Gmail, phone, founding date, awards, staff count or invented customer data.
- Person: existing confirmed identity plus full-profile approval and indexability gate. The helper is wired to the founder route and tested positively with an isolated approval fixture, but current full details remain draft and emit no Person schema. No photo is required or guessed.
- Service: only explicitly approved offerings. All current services remain provisional, noindex and without Service schema. Positive helper tests do not change production records.
- Project: approved publication, ownership, status, exact role, summary and display permission are required. CreativeWork is used conservatively, with only approved service/person relations. Company ownership does not imply sole authorship; no `creator` is inferred from it. No result/award/rating is synthesized.
- Article: actual section text, verified author, valid dates and an approved named review are required. Drafts, missing bodies, unsupported author slugs, future/invalid dates or missing review cannot enter routes/listings/sitemap/schema. The real collection is empty. Synthetic fixture prose/byline is only test data outside `src/content/articles`, never a public route.
- BreadcrumbList: mirrors visible semantic breadcrumb navigation on detail/editorial pages. Root IDs connect to Organization/WebSite consistently.

JSON-LD uses one escaping helper against script termination/line-separator injection. Business schema is gated by configured origin/indexability. These are semantic data types, not promises of Google rich results. Guidance checked against [Google Organization](https://developers.google.com/search/docs/appearance/structured-data/organization), [Google Article](https://developers.google.com/search/docs/appearance/structured-data/article) and [Schema.org Service](https://schema.org/Service); only substantiated fields are included.

## Writing and cross-linking

Content stays in local TypeScript collections; the article model has semantic sections, paragraphs, optional lists/code, topics, sources, byline, real dates and review. Do not invent an author/date or set approval just to populate a template. `docs/SEO_CONTENT_BRIEFS.md` supplies intent/outline/evidence/review briefs only, not unpublished posts disguised as content.

The article template has a semantic contents list, source links, responsive code blocks, author profile when exact identity matches, related approved services/cases and a contact CTA. Service pages link approved matching cases; case templates link approved service slugs and precise approved personal contributions. Founder/company work remains separate. Empty relations stay honest. Additional founder-independent work must never become a MOTEKRA engagement through cross-linking or schema.

The five main navigation links remain the approved composition. Insights is absent while there are no publishable posts; the footer adds its link only when reviewed posts exist. `/insights` remains an accessible noindex empty state. Unknown/draft article and case slugs return actual 404s.

## Discovery

`approvedSeoPaths` is the shared sitemap registry. Only approved service pages, full profiles, cases and genuine articles are added; empty Insights and provisional offerings are omitted. No artificial last-modified dates are generated from build time.

Preview robots disallow all. In configured/indexable mode robots allows normal content, excludes technical API/lab/retired evidence paths, and links the sitemap. Draft pages use noindex rather than a blanket crawl block, so future approved service/founder/Insights paths are not permanently excluded. Readiness flags do not prove indexing or approval. Deployed status codes, canonical host/HTTPS redirects and robots behavior must be checked on the chosen host.

## Reproduce checks

1. `pnpm check` validates strict types, lint, unit tests and the normal noindex production build.
2. Start that build, run `node scripts/seo-audit.mjs preview` and `pnpm test:seo`.
3. For a **local configured fixture only**, build/start with process-local `SITE_URL=https://example.test` and `SITE_INDEXABLE=true`, then run `node scripts/seo-audit.mjs configured`. Never deploy this fixture or write these values into real environment files.
4. Stop the fixture server, clear those process-local flags and rebuild normally. The final stored build must be restored to preview while approvals/domain are pending.

Audits collect initial served HTML with JavaScript disabled, metadata, parsed JSON-LD, headings, body/links, sitemap/robots and unapproved 404s across 12 real routes. Browser tests cover empty Insights, fixture-only article layout, keyboard contents anchors, no JS/WebGL, static social assets and desktop/mobile axe. Neither local scripts nor a Lighthouse score proves production crawling/indexing.
